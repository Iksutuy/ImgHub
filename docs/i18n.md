# 多语言（中 / 英 / 日）实现记录（v0.5.40）

> 目标：界面支持中文 / English / 日本語，并能在**设置里切换**（即时生效，无需重启）。
> 本文记录**方案选型、踩坑全过程、最终机制**，以及新增文案时要改哪里。

---

## 一、结论速览（给后来者的最短路径）

| 问题 | 答案 |
|---|---|
| 文案存在哪？ | `src/ImgHub.App/Ui/Localizer.cs` 里三个**普通 C# 字典**（`Zh` / `En` / `Ja`） |
| XAML 怎么取？ | `{CompiledBinding L[key]}`（`L` 是 `MainViewModel` 上暴露的 `Localizer` 属性） |
| 怎么切语言？ | 改 `Localizer.Instance.Language`（VM 的 `Language` / `LanguageIndex` 会转发） |
| 为什么不用 .resx？ | AOT 下会炸（见 H1：反射式资源查找被禁用） |
| 为什么不用 `{DynamicResource}`？ | 实测**运行时替换后不推送更新**（见下"坑 1"） |
| 新增一条文案要改哪？ | 三个字典各加一条（键必须一致，有测试钉住）+ XAML 用同一把键 |

**当前规模**：**233 个键 × 3 语** = 699 条文案；XAML 238 处 + VM 13 个属性已接入。

## 二、方案选型（以及被否决的方案）

### ❌ 否决：`.resx` + `ResourceManager`

.NET 的 `.resx` 走**反射查找资源**。本项目是 Native AOT，反射序列化/资源查找默认被禁用
（`docs/CONSTRAINTS.md` H1 有完整记录：`config.json` 曾因此读不进 → 参数全默认）。
**代价**：AOT 下要么炸、要么静默失败。

### ❌ 否决：Avalonia `{DynamicResource}` + 替换资源字典

看似最"Avalonia 原生"。**实测否决**：

- 写了探针测试，替换 `Application.Resources[key]` 后，**已构建控件不会更新显示**
  （`DynamicResource` 只在控件附加到资源树时解析一次）。
- 后果：切语言必须**重建整个界面** —— 代价大且容易丢状态（滚动位置、编辑中的标注……）。

### ❌ 否决：第三方 i18n 库

本项目 `docker` / `make` 不可用、尽量少依赖；且多数库依赖反射或 .resx。

### ✅ 采用：静态字典 + `INotifyPropertyChanged` + 编译绑定索引器

```
Localizer（单例, INotifyPropertyChanged）
    ├─ Zh / En / Ja   三个普通 C# 字典（编译期嵌入程序集 → AOT 天然安全）
    ├─ this[string key] 索引器 → 按当前语言取文案
    └─ Language setter → 逐个键发 Item[key] 通知

XAML: {CompiledBinding L[key]}   ← L = MainViewModel.Localizer 属性
```

**为什么能即时切换**：切语言 → Localizer 发通知 → 编译绑定重新求值索引器 → 界面刷新，**不重建控件**。

## 三、踩坑全过程（**六个坑，按发现顺序**）

### 坑 1：`DynamicResource` 运行时替换不生效（选型阶段）

- **怎么发现的**：写探针测试替换 `Application.Resources["ProbeKey"]`，断言"控件文本应变化"。
- **结果**：不变化。⇒ 明确否决该方案。
- **教训**：不要凭"文档说支持动态资源"就选型 —— **实测一次**。

### 坑 2：`{CompiledBinding [key], Source={x:Static ...}}` —— 编译期报"没有索引器"

最初 XAML 写的是：

```xml
<TextBlock Text="{CompiledBinding [app.title], Source={x:Static ui:Localizer.Instance}}"/>
```

**编译期**报错（这是好事，编译绑定会检查）：

```
AVLN2000: The type 'ImgHub.App.ViewModels.MainViewModel' does not have an indexer.
```

⇒ **`CompiledBinding` 会忽略 `Source=`，仍按 `x:DataType` 推断源类型**（此处 = `MainViewModel`）。

**修法**：在 VM 上暴露一层属性 `public Localizer L => Localizer.Instance;`，
XAML 写 `{CompiledBinding L[key]}` —— 这样编译期检查的就是 `L` 的类型（有索引器）。

### 坑 3：⚠️ **索引器通知名必须是 `Item`**（最难查，两次才查准）

**现象**：一切都对，就是界面不变：

- 配置读到了 `en` ✅（日志：`配置读到的=[en]`）
- `Localizer.Instance.Language` 是 `en` ✅
- 代码里取值正确 ✅（探针 `Localizer.Instance["app.title"]` → `ImgHub Workbench`）
- **界面上仍是中文**，且**不报任何错**

**排查过程（走了一次弯路，值得记录）**：

| 尝试的通知名 | 结果 |
|---|---|
| `string.Empty`（"所有属性都变了"） | ❌ 不刷新（那是**经典绑定**的约定） |
| `Item[key]`（如 `Item[app.title]`） | ❌ 不刷新 ← **看起来最像，其实是错的** |
| `Item[]` / `[key]` / `key` | ❌ 不刷新 |
| **`Item`** | ✅ **刷新** ← Avalonia 12 认的就是这个 |

`Item` 是 C# 索引器的**元数据属性名**（`this[...]` 编译成 `get_Item`/`Item`）。
Avalonia 的绑定监听源对象的 `PropertyChanged("Item")` → 用**自己的 key** 重新求值索引器。
⇒ **只发一次 `Item` 就够**（不必逐键发 213 次）。

**⚠️ 上一轮为什么会误判（教训）**：
上轮我写了断言"**发出过** `Item[key]` 通知"的测试 → 它**通过了**，
因为测试只验证了"通知被发出"，**没验证"通知真的让绑定刷新"**。
⇒ **测"通知"必须测到"订阅者侧的效果"，否则是假通过。**

**本轮的正确做法**：用假源（同形的索引器 + `INotifyPropertyChanged`）
**穷举候选通知名**，观察哪种能让绑定真正重取 —— 这才定位到 `Item`。

**⚠️ 又踩到：测试之间的单例污染**
`Localizer` 是进程级单例，xunit **并行**跑不同测试类 → 一个切 `en`、另一个断言中文 ⇒
单独跑通过、**一起跑必失败**。
修法：`[CollectionDefinition(DisableParallelization = true)]` +
各测试类标 `[Collection(LocalizationTests.Name)]`（见 `LocalizationTests`）。
另外**不要**在测试里用真实 `Binding` 做端到端断言 ——
真实绑定求值依赖 `Application.Current` 等全局状态，xunit 全量跑时会被其他测试影响
（实测：单独跑通过、全量跑 `Text` 直接是 `null`）。
⇒ 只测**通知机制本身**；真实端到端行为靠**人工点击验证**（本轮已截图确认）。

### 坑 4：`ContextMenu` 是独立视觉树 → 编译绑定取不到 VM

`ContextMenu` 里的 `MenuItem` 用的是**经典绑定**（它不继承 DataContext）：

```xml
<!-- ❌ 编译绑定报 AVLN2000: of name 'L' on type 'System.String' -->
<MenuItem Header="{CompiledBinding L[hist.removeOneTip]}"/>

<!-- ✅ 显式给源 -->
<MenuItem Header="{Binding [hist.removeOneTip], Source={x:Static ui:Localizer.Instance}}"/>
```

**为什么这里反而该用经典绑定**：`ContextMenu` 不在主视觉树里，DataType 推断本来就不适用；
显式 `Source` 是这种情况下**唯一正确**的写法（本项目共有 3 处）。

### 坑 5：⚠️ **VM 里"动态生成文案"的属性也要本地化**（用户报"完全没变化"的第二个根因）

上一轮只把 **XAML 里的字面量**接进了 Localizer，**漏了 VM 里拼装文案的属性**：

```csharp
// ❌ 硬编码 → 切到英/日时这些地方**不会变**
public IReadOnlyList<string> ToolNames { get; } = new[] { "方框", "圆圈", "马克笔", "橡皮" };
public string RegionCountText => RegionCount == 0 ? "尚未圈画" : $"已标注 {RegionCount} 处";
public string HistoryMultiButtonText => HistoryMultiSelect ? "完成多选" : "多选";

// ✅ 改走 Localizer（注意带参数的用 T(key, args)）
public IReadOnlyList<string> ToolNames => new[]
{
    Localizer.Instance["region.toolRect"], Localizer.Instance["region.toolEllipse"],
    Localizer.Instance["region.toolMarker"], Localizer.Instance["region.toolEraser"],
};
public string RegionCountText => RegionCount == 0
    ? Localizer.Instance["region.none"]
    : Localizer.Instance.T("region.count", RegionCount);
```

**本轮补齐的清单**（13 个属性）：
`ToolNames` / `RegionCountText` / `EditTip` / `GenerateTip` / `RegionEditTip` /
`ExtractHint` / `GuideActiveHint` / `PolishStyleNames` / `PolishStyleLabel` /
`SetupHint` / `BatchNHint` / `HistoryMultiButtonText` / `PromptMultiButtonText`

**防护测试**：`LocalizationContractTests.ViewModelBoundStrings_AreLocalized_NotHardcodedChinese`
用源码扫描断言这些属性里**不得出现中文字面量**（注释除外）。

### 坑 6：⚠️ **计算属性改了 Localizer 还不够 —— 必须显式发通知**（最隐蔽）

坑 5 修完后，切英文时界面大部分变了，但 **「多选」按钮仍是中文**。

**根因**：`{CompiledBinding L[key]}`（索引器绑定）会随 Localizer 的通知自动刷新，
但 VM 里的**计算属性**（`HistoryMultiButtonText` 等）是**普通属性** ——
Avalonia 只认 `OnPropertyChanged(nameof(X))`，**不会**因为它内部读了 Localizer 就重取。

**修法**：新增 `NotifyLocalizedStrings()`，切语言时统一通知这 13 个属性：

```csharp
private void NotifyLocalizedStrings()
{
    OnPropertyChanged(nameof(ToolNames));
    OnPropertyChanged(nameof(RegionCountText));
    // … 共 13 个（清单见坑 5）
}
```

**⚠️ 新增"会随语言变化的 VM 属性"时，必须同时加进这个列表** ——
测试 `EveryLocalizedVmProperty_IsNotifiedWhenLanguageChanges` 会检查覆盖度。

## 三·补：三个坑的**共同特征**

| 坑 | 症状 | 一句话根因 |
|---|---|---|
| 1 `DynamicResource` | 切换后不变 | 只在附加到资源树时解析一次 |
| 3 通知名 | 切换后不变，代码取值却对 | 索引器绑定**只认 `Item`** |
| 5 VM 属性 | **部分**界面不变（如工具下拉、「多选」） | 漏了 VM 里拼装文案的属性 |
| 6 未发通知 | 坑 5 修完后**仍部分不变** | 计算属性需**显式** `OnPropertyChanged` |

**统一的诊断套路**（"代码对、界面不对、不报错"）：
① 配置读到了吗 → ② 单例值对吗（**打日志打印你以为对的东西**）→
③ 通知名对吗（索引器 = `Item`）→ ④ 绑定路径对吗 → ⑤ **VM 侧属性是否也本地化 + 是否发了通知**

## 四、如何新增一条文案

1. **改 `Localizer.cs`**：在 `Zh` / `En` / `Ja` **三个字典各加一条**（键必须一致）：

   ```csharp
   // Zh
   ["myFeature.title"] = "我的功能",
   // En
   ["myFeature.title"] = "My feature",
   // Ja
   ["myFeature.title"] = "マイ機能",
   ```

2. **XAML 里用**：

   ```xml
   <TextBlock Text="{CompiledBinding L[myFeature.title]}"/>
   ```

3. **跑测试**：`LocalizationContractTests.AllThreeLanguages_HaveExactlyTheSameKeys`
   会在键不一致时报出**具体缺哪些键**。

### ⚠️ 五条硬约束

| 约束 | 原因 |
|---|---|
| **三个字典的键必须完全一致** | 缺一条会静默回退中文 → 日文用户看到"半中半日" |
| **不要用 `{DynamicResource}` 取文案** | 运行时切换不生效（坑 1） |
| **`ContextMenu` 内用 `{Binding [k], Source={x:Static ui:Localizer.Instance}}`** | ContextMenu 是独立视觉树（坑 4） |
| **VM 里拼装文案的属性也要走 Localizer** | 否则切语言时"部分界面不变"（坑 5） |
| **该属性还要加进 `NotifyLocalizedStrings()`** | 计算属性需**显式**通知才会刷新（坑 6） |

### 在 VM 里新增"随语言变化的文案属性"（完整步骤）

1. 属性内部读 `Localizer.Instance["键"]`（带参数用 `.T("键", args)`）
2. **加进 `MainViewModel.NotifyLocalizedStrings()`**：

   ```csharp
   OnPropertyChanged(nameof(MyNewText));
   ```

3. 跑 `LocalizationContractTests`：两条扫描测试会提醒你漏了哪一步
   （`ViewModelBoundStrings_AreLocalized_NotHardcodedChinese` + `EveryLocalizedVmProperty_IsNotifiedWhenLanguageChanges`）

## 五、译文质量说明

英 / 日译文由 AI 按**通用技术译法**生成（生成→Generate/生成、蒙版→Mask/マスク、蒙版说明→Mask help/マスクの説明……），
**未经母语者校对**。要改译文**只需改 `Localizer.cs` 的字典**，不必动任何 XAML。

需要校对时的定位方式：搜 `Localizer.cs` 里的键名（如 `region.maskHint`），
三个语言各一行，改对应行即可。
